# 数据库文件

数据库固定使用 MySQL 8.4，连接信息从环境变量读取。

- `schema.sql`：创建 `sys_user`、`charity_project`、`donation`。应用启动自动执行 `CREATE TABLE IF NOT EXISTS`，随后由 Hibernate 校验映射；不删除已有表或记录。它不是数据库迁移工具，已有表结构变化需后续显式迁移。
- `demo-projects.sql`：只在 `DEMO_DATA_ENABLED=true` 时执行，初始化一个募集中项目和一个草稿项目。同标题已有项目会跳过，不覆盖已修改内容。仅支持本地单实例初始化；不承诺多个应用实例并发初始化。
- 管理员由后端 `DemoDataService` 用环境变量创建并使用 BCrypt 保存，不在 SQL 中写入明文密码。已有同名管理员保持原密码；同名普通用户会导致初始化失败，不自动提升权限。

数据库本身需要提前创建，示例：

```sql
CREATE DATABASE IF NOT EXISTS charity_donation
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

应用启动账号需要此数据库内建表及业务读写权限。初始化不会执行清库、删表或覆盖业务数据。用户名与提交标识使用区分大小写的字段排序规则。

金额字段为 `DECIMAL(12,2)`，正数 CHECK、唯一约束和限制删除的外键已建立。MySQL 对多余小数的处理不能替代后端精度校验；第四阶段已在请求 DTO 校验正数、精度和范围，非法金额在写库前拒绝，不静默取整。

捐款事务先锁定当前用户，再查询提交标识；相同项目、金额返回原记录，不同内容返回409。首次提交还会锁定项目并检查 ACTIVE，和项目结束操作使用相同行锁。已有 `(user_id, request_id)` 唯一约束作为数据库防线。本次只验证顺序重试，没有执行并发或压力测试。

募集金额、项目捐款笔数及后台总额从 donation 汇总，不添加累计字段。第四阶段沿用已有三张表，无需修改建表脚本或执行清库。
